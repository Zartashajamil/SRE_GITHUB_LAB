
# Parking Inventory System

## Overview

The Parking Inventory System is a centralized digital platform designed to help parking operators manage parking transactions, vehicle information, invoices, parking locations, employees, and revenue.


## Scope

### In Scope
- In scope: Record parking transactions using vehicle numbers and vehicle categories (car/bike).
- In scope: Generate parking invoices/tokens with applicable parking charges.
- In scope: Manage multiple parking locations and their car/bike prices.
- In scope: Manage employee and administrator accounts, roles, and assigned locations.
- In scope: Search, filter, and view parking invoice records.
- In scope: Generate customized parking reports.
- In scope: Monitor revenue, vehicle counts, and other dashboard statistics.
- In scope: Support thermal printing and Bluetooth printer connectivity.

### Out of Scope
- Out of scope: Individual parking-slot allocation and real-time parking-space availability.
- Out of scope: Vehicle exit recording and parking-duration-based billing.
- Out of scope: Customer self-service parking transaction entry.
- Out of scope: Online payment processing and customer payment gateways.
- Out of scope: Automatic vehicle number recognition through cameras.
- Out of scope: Predictive parking analytics and automated parking optimization.

## Stakeholders

- **Administrator:** Manages employee accounts, user roles, parking locations, location-specific prices, and system information.
- **Parking Employee:** Records vehicle parking transactions, generates invoices/tokens, and handles daily parking operations.
- **Parking Management:** Monitors parking activity, revenue, invoice records, and reports across different locations.
- **Parking Customers:** Receive parking tokens/invoices generated by employees and pay the applicable parking charges.
- **Project Maintainer:** Maintains project documentation, analyzes system requirements, and ensures requirements remain organized and consistent.

## Functional Requirements

- FR-01: The system shall allow authorized employees to create parking transactions by entering vehicle numbers.
- FR-02: The system shall allow employees to select vehicle categories, including cars and bikes.
- FR-03: The system shall record the parking transaction date and time.
- FR-04: The system shall associate each parking transaction with a parking location.
- FR-05: The system shall generate a unique parking token or invoice number for each transaction.
- FR-06: The system shall apply the appropriate parking charges based on vehicle category and location.
- FR-07: The system shall record the employee responsible for creating a parking transaction.
- FR-08: The system shall allow authorized users to search, filter, and view parking invoice records.
- FR-09: The system shall allow administrators to add, edit, and manage employee and administrator accounts.
- FR-10: The system shall allow administrators to manage parking locations and their vehicle-specific prices.
- FR-11: The system shall provide dashboard statistics related to revenue, invoices, and parked vehicles.
- FR-12: The system shall allow authorized users to generate customized parking reports using available filters.
- FR-13: The system shall support thermal printing and Bluetooth printer connectivity for parking invoices.

## Nonfunctional Requirements

- NFR-01: The system shall provide an organized and understandable interface for administrators and parking employees.
- NFR-02: The system shall restrict access to administrative and employee operations according to authorized user roles.
- NFR-03: The system shall maintain consistent and accurate parking transaction information across invoice records and dashboard statistics.
- NFR-04: The system shall provide timely access to parking records and dashboard information during normal operation.
- NFR-05: The system shall protect user account information and prevent unauthorized access to system data.
- NFR-06: The system shall provide a reliable mechanism for storing and retrieving recorded parking transactions.

## Acceptance Criteria

- FR-01: Given a valid vehicle number, an authorized employee can create a parking transaction successfully.
- FR-02: Selecting Car or Bike records the correct vehicle category for the transaction.
- FR-03:The system should  its recorded date and time.
- FR-04: Selecting a parking location associates the transaction with that location.
- FR-05: Creating a transaction generates a unique token or invoice number.
- FR-06: Given a vehicle category and parking location, the transaction displays the applicable parking fee.
- FR-07: A created invoice displays the employee responsible for the transaction in the Records section.
- FR-08: Searching or filtering invoice records displays transactions matching the selected criteria.
- FR-09: An administrator can add a user and update existing user information.
- FR-10: An administrator can manage parking locations and their car and bike prices.
- FR-11: The dashboard displays parking statistics, including revenue and vehicle counts.
- FR-12: Generating a report using selected criteria produces a report for the requested information.
- FR-13: When a compatible thermal printer is connected and configured, the system supports invoice printing.

## Assumptions and Open Questions

### Assumptions
- A-01: Parking transactions are created by authorized employees rather than directly by customers.
- A-02: Each parking transaction represents a parking entry for a particular vehicle.
- A-03: Parking charges are determined by vehicle category and the selected parking location.

### Open Questions
- Q-01: Does the system support editing or deleting previously generated invoices, and what permissions apply?
- Q-02: Are parking charges fixed per transaction, or can they vary according to parking duration?
- Q-03: Does the system use a centralized server for storing transaction data and generating timestamps?
